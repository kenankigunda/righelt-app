## Scope

- Add hamburger menu to game-page header chrome (consistent position with home-page card):
  - Uses `renderCardMenu` (from t-030.05) with a game-page variant call site.
  - Leave/Delete action wires to `transport.leaveGame(gameId)`.
  - Viewer leave wires to `transport.leaveAsViewer(gameId)` then navigates to join-decision screen (`buildInviteHash` with the game's invite token, or `buildGameHash` with `?from=Viewer`).
- Add "Game deleted" blocking overlay for game-page route:
  - Shown when `game.deletedAt !== null` while any participant is on the game route.
  - Reuses `invite-gate` CSS pattern: full-width top-of-page, background `aria-hidden="true"`.
  - Shell must not initialize or resume a board session when `deletedAt` is set.
  - Animates in (120–220ms, respects `prefers-reduced-motion`).
  - For players: shows "Game deleted" heading and "Restore" action button.
  - For viewers: shows "Game deleted" heading only — no Restore button.
  - "Restore" calls `transport.restoreGame(gameId)`.
  - On successful restore: clear deleted state, re-render game normally (re-initialize board if needed), without full page reload.
- Handle `game_deleted` WebSocket event in `app.js` render loop:
  - If current route is the affected game: show "Game deleted" overlay immediately.
- Handle `game_restored` WebSocket event:
  - If current route is the affected game: remove overlay and re-initialize live game view.
- "Game not found" screen render:
  - When game route is loaded and `loadGameProjection` returns null (game does not exist in DB): set route to `game-not-found`.
  - Render: minimal centered shell state, single heading "Game not found", no board surface, no restore option.
- Playground mode: `computeLeaveDeleteLabel` returns "Delete" when `selfPlayMode === true`; action goes through the soft-delete path (same as last-player delete).
