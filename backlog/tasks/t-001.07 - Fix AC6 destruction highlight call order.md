## Description

The `jump-destruction` handler in `app.js` calls `boardRuntime.setDestructionHighlight({row, col})` BEFORE `syncRouteDataAndLiveChannels()`. When clicking a sub-bullet from live mode or from a different history move, the snapshot changes — `mountBoardForGame` calls `loadSnapshot`, whose first line sets `destructionHighlight = null`, clearing the highlight before it can render.

## Fix

Move `boardRuntime.setDestructionHighlight({row, col})` to after the `await syncRouteDataAndLiveChannels()` call in the `jump-destruction` handler.

## Acceptance Checks

- Clicking a destruction sub-bullet from live mode sets the highlight on the correct square
- Clicking a destruction sub-bullet from a different history move sets the highlight on the correct square
- `pnpm --filter @righelt/web test` passes with 0 failures
- Add or update a test asserting `setDestructionHighlight` is called after `selectHistoryMove` in the source
