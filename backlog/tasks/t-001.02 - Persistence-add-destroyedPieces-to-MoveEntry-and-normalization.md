## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Extend the persistence layer to store destruction records on every move:

- Add `destroyedPieces?: DestroyedPieceRecord[]` to the `MoveEntry` type in `shell-live-core.ts`.
- In `recordClientMove`, save the computed `destroyedPieces` array onto the `MoveEntry` before `game.moves.push(move)`.
- Add normalization shim in `shell-live-db.ts`: moves without `destroyedPieces` default to `[]` with a mismatch log entry (no backfill for pre-deploy moves — clean break).
- Update duplicate-move response paths to pass through `move.destroyedPieces`.
- Update response types in `game-room-do.ts` and `shell-live.ts` so `destroyedPieces` is included in move responses and history endpoint payloads.

No replay-based backfill is needed for existing moves.
