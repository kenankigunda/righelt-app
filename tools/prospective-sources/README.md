# Prospective source preparation

This is a synthetic-only preparation library for the independently reviewed T-122 prospective-source contract and its hiding-commitment/schema clarifications. It has no CLI, trainer hook or image entrypoint. `executionMode: operator` rejects before any reservation or callback. The callback fixtures use invented data. They never import the engine, model, real source inventory or protected data.

The new producer is separately identified by revision, implementation bytes, dependency/configuration/runtime identities and exact versioned schema bytes. The reused017 primitive identities are static inspection bindings, not qualification of this new adapter. Every output claim remains false, including operator execution, native inventory, guard qualification, strength, scientific admission and private final consumption.

## Reservations and metadata

One private assignment binds authority, producer/schema/primitive/custody identities, registry/exposure inputs, all ordered reservations, the original deadline, attempt cap and selection rule. Each reservation commitment uses canonical sorted JSON, a declared versioned domain and a private 32-byte nonce. The entire private assignment digest is included inside that nonce-hiding commitment. A plain seed hash or physical manifest digest is never substituted for a hiding commitment. Only synthetic fixtures can override nonce creation.

Ordinary metadata contains only the schema's declared public identity projection, opaque reservation/capture commitments, fixed attempt categories, selected commitments and false claims. Private input digests, seeds, reservation/source-family IDs, parent mappings, nonces, raw states/actions and private recovery identities are omitted. Public capture commitments hide the distinct physical constructor/verifier file descriptors. Failed commitment openings reject. The output projection returns copies and cannot mutate private state.

Registered family relationships form dependency components, with one selected reservation per component in fixed reservation order. Cross-partition relationships or unregistered parents reject the assignment. Exposed, unresolved or quarantined relationships quarantine the entire component. A null family is preserved and excluded before dispatch. No alias, root or seed repairs missing lineage or creates a family ID. Unrelated canonical normal roots are shared public context, so their common geometry does not collapse independently registered game families. Developed state/fingerprint/guard duplicates quarantine proposals rather than granting additional family credit. Guard domains remain distinct. Typed guard values preserve the native encoded hash and full `simple:<sha256>` commander alias, without stripping the prefix or silently treating one representation as another. Actual protected collisions reject, with no normal-start waiver.

## Attempts and local custody

The append-only journal records the full reservation before dispatch and `began` before invoking a callback. Constructor bytes are captured privately before parsing or verification. Verifier bytes are separately captured before parsing their result. Missing, rejected, quarantined and interrupted work remains consumed. Selection waits for the entire original finite assignment to settle without missing output. Neither restart nor a result creates another seed or extends the deadline. Elapsed attempt time is retained in the private journal.

The local filesystem proof uses private directories/files, no-follow reads, write-once raw files, compare-and-append revisions, an exclusive writer lock, immutable hash-linked journal records and file/directory synchronization. An incomplete pending record or stale lock fails closed for review. It does not qualify a backup, remote recovery, rollback-resistant external anchor or production durability boundary. There is no cleanup API that could discard private evidence. Synthetic tests remove only their own temporary fixtures.

`openPostLock` always rejects with a fixed unavailable category. A candidate digest alone is not lock authority. `verifySeedOpening` can validate an already-held mapping, but the preparation interface never returns a raw final seed or schedule. Journal reads remain a private custody interface, never ordinary metadata. The actual authorized candidate-lock receipt and existing private final-consumption path still require a separate reviewed integration.

No real generation, seed/nonce allocation, protected read, source selection, corpus transfer, scientific activation or current9f image amendment is authorized by this library or its tests.

Normal/developed scientific scope remains separate from full-board, long/repetitive and legal-continuation readiness. This library proves none of those executed coverage slots.
