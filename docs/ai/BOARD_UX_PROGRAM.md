# Board and computer play acceptance

This program follows the October 2026 product decisions. Independent healthy PRs may deploy in sequence. The lead owns the final combined result. All production games, including synthetic smoke-test games, must be preserved as training data. Preserve their move history, durable receipts and model provenance. Do not run production game deletion, destructive migrations or retention cleanup. Account activation and evidence publication require separate authorization.

## Interaction contracts

- Pass is available at the start of a human turn alongside the other top-level actions. Choosing a piece or preview does not start an action. An accepted action does. Ending a legal continuation is End Turn for humans, computers and training. Required supply, retreat and follow obligations remain enforced. End Turn has durable evidence but no move row or move number.
- The commander and supply legend controls inspect the selected piece, or the side to move when nothing is selected. An unoccupied supply point inspects all paths to that point. Pieces and legal destinations take priority. Inspection works while computer actions run. Commander reclicks cycle through the agreed piece and network views.
- Board messages describe the current task briefly. Computer turns replace human prompts with thinking, preparation or completed-action narration. Show me again visually replays the acknowledged computer turn over an isolated board. It never submits, searches, selects history or mutates the live game. Stop, navigation, backgrounding, account changes, undo and new live revisions cancel playback. Reduced motion uses static manual steps.
- Thinking copy has no literal ellipsis. The animated loading pieces supply the cue and keep their identity across preparation, search and save. Recovery, history, replay and paused states stop the cue.
- Play again and Create a new game here use mutually exclusive native opponent mini cards, with the current opponent selected. Portraits, cut corners, keyboard arrows, visible focus and 44-pixel labels follow the existing design. Readiness updates preserve selected controls and focus. Start stays disabled while the source game is recovering, and actual start errors persist through background updates.
- Thinking, saving and related activity animations use the responsible player’s red or blue. Pending work keeps its captured actor after optimistic turn advancement, including defender-controlled retreats. Color updates preserve node identity and animation time. Unknown-actor page loading retains the dual-color brand treatment.
- A valid unresolved receipt remains pending with its original durable command, retry ownership and deadline. Actual request failures show an immediate static error. Recovery offers icon-labeled Reload game and Home actions without discarding pending intent.
- Ordinary thinking exposes no recovery CTA. Preparation detail starts after 5 seconds, Interrupt after 30 seconds, and save feedback after 10 seconds in the save phase. Actual failures appear immediately. Slow feedback lives outside the board card.
- Connection recovery notices count only visible time waiting on blocked live play in the active game. Show a quiet notice after 4 seconds and stronger recovery actions after 15 seconds. Returning from a hidden tab, changing games or accounts, entering history, and settled recovery reset this presentation wait. An overdue background command cannot bypass the fresh grace. Durable command deadlines, lease authority and retry timing remain wall-clock based. Authentication, update, invalid-response and local-storage failures remain immediately actionable. Recovery notices stay separate from board task messages.
- Before a gameplay command is admitted, computer play automatically retries temporary resource/evidence request failures, HTTP 408/429/5xx, incomplete transfers and request timeouts. Client backoff caps at 5 seconds, while a longer server Retry-After is honored. A completed evidence write with a lost response is read back by the same attempt ID and compared to its exact JSON payload before an identical write or submission. It must never be replaced with unfinished evidence. A completed decision survives temporary admission fences without another calculation, attempt ID or evidence rewrite while its scope, revision, fingerprint and control generation remain current. Retries recheck game, account, transport, revision, state fingerprint, control generation and live acknowledged lease. Scoped cancellations discard the old unadmitted decision. After gameplay admission, only the durable journal owns retries and receipt reconciliation. Integrity, protocol, ownership, authentication and storage failures remain explicit recovery states. Pre-admission retry notices reuse the foreground 4/15-second clock outside the board, with Retry available after the stronger threshold.

## Space and history

- Board heading and message geometry stay stable through selection, thinking and narration, including 200% text at narrow widths. Hidden inaccessible sizing replicas use the actual type and narration so ordinary text stays compact. Loading uses the same shell and board geometry as the settled page. Home uses the same card and preview structure before data arrives. Existing content stays mounted through refresh and pagination. A socket snapshot arriving before route hydration uses the same canonical game shell and authority gates, with no intermediate legacy board frame.
- Narrow layout has one document scroller. Inactive panels do not contribute height. The header uses one row, with Account in the menu. Three lightweight icons provide Players, Board and History. Navigation hides after 3 seconds idle or 24 pixels down, and returns after 12 pixels up, panel entry or its accessible handle. Keyboard interaction, safe areas, scroll restoration and overscroll must not cause accidental hiding or interception.
- Narrow Board always projects the live game. History groups moves beneath `Turn X · Player Name`, newest turns first and chronological moves within each turn. Selecting a move or turn shows the same overlays in desktop and mobile. Individual selected entries are inert while their child actions remain interactive. Turn summaries have no undo/new-game actions. See [History presentation](HISTORY_PRESENTATION.md) for source/target colors, aggregate routes, frozen selections and mobile reveal. Players preserves selection. Any return to Board clears history before revealing it. Return to live also switches to Board. Resizing carries the selected view between layouts.
- Accepted undo returns only its requester to live, provided they have not changed history selection since initiating it. Browsing away and back still counts as a change. Inspection and visual replay do not. Pending undo remains a notice so browsing remains possible. Other viewers retain their own selections. Archived decisions use authoritative restoration identity.

## Motion and presentation

- Notifications retain incident identity, focus, open details and animation time during updates. Active work pulses its whole surface every 2.4 seconds. Waiting for a human uses a slower 4-second pulse. Copy and controls stay steady. Errors, completion and paused states are static. A new urgent notice must not hide a focused or expanded notice.
- Loading sweeps have crisp red and blue facets, smooth transforms and no blended edge or blur. An independent reviewer inspects the sweep, pulses, replay and narrow layout together for coherence with Righelt's stone-cut design.
- Computer home cards name the opponent rather than saying both players. User-facing experimental copy and redundant UI instructions are removed. First-use explanatory tooltips are deferred.

## Game results

- A commander removed during a push is described as destroyed, separately from an existing commander losing supply. Old terminal snapshots retain their original stored data; presentation derives the precise cause from that saved position.
- Seated players see a larger You won or Your opponent won heading, with Your commander or Your opponent’s commander in the explanation. Observers get neutral wording and draws retain Draw. The You won commander image and animated fragments use the winning user’s actual side color, red for Red and blue for Blue. Images, finite motion and sound follow the result perspective, sound preferences and reduced motion. Only an observed live finish starts the effect. History, reload and manual result opening remain quiet. Enlarged text keeps words intact and actions reachable.

## Validation and release

Use the pinned released validation tools, an explicit candidate checkout and exact revisions. Preserve raw failures and repair the canonical source PR. Evidence publication remains paused. Merge readiness, user merge authority and deployed production verification are separate gates.

| Area | Required proof |
| --- | --- |
| Rules and model | Engine legality, required obligations, optimistic/server parity, durable receipts, imported continuations, no fabricated history rows, original model/config identity and real shipped-model inference |
| Computer UX | Frame-by-frame board geometry, independent think/save clocks, no early CTA/banner, immediate failures, full-turn narration, actual model reload and undo |
| Opponent picker | Current opponent and side, all five choices, native keyboard selection and focus, loaded portraits, narrow dialog actions, preparation and retry, source recovery, Cancel/reopen and stale completion |
| Replay | Actual renderer, stacked push/retreat/follow/removal, source and destination transforms, cancellation, reduced motion, immutable live state and no API writes |
| History and undo | Narrow after-state mini preview, hidden live Board updates, panel detours, resize, self-play and friend approval, unchanged intent, away-and-back, other viewers and archived restoration |
| Navigation and layout | Chromium and touch WebKit, 320–430 widths, landscape, breakpoint edges, single scrolling, inactive-panel height, safe areas, text expansion, keyboard focus and idle/upscroll |
| Loading and notifications | Cold and warm Home/game/invite entry, delayed data and pagination, transient DOM/recordings, stable keyed nodes and pulse timeline, urgent arrival during focus/details, reduced motion |
| Results | Actual push/removal/follow in engine and browser runtime, legacy saved outcome unchanged, winner/loser/spectator/self-play/draw copy, finite motion and sound lifecycle, 200% text and real authenticated result/history/reload/rematch |
| Release | Required exact-head CI, bounded independent code and visual review, combined retained/current-contract proof, deployment artifact identity and production smoke |

Physical iPhone checks supplement browser automation: Safari chrome resizing, rubber-band scroll, edge swipe and safe-area behavior. Record any unavailable physical-device proof as a gap, never as a passed check.
