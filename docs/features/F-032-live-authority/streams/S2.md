# Stream S2 - Backend Rewrite To GameRoomDO

## Scope
- Implement `GameRoomDO` as the sole writer for live game state.
- Rewrite shell live backend routing so all game-scoped mutations and websocket sessions go through the DO.
- Remove the old in-memory subscriber fanout and legacy shell websocket path.

## Non-Goals
- No frontend rendering or route-state rewrite.
- No home-page polling redesign.
- No offline playground architecture changes beyond preserving current behavior.

## Deliverables
- New `packages/api-handler/src/game-room-do.ts`.
- Rewritten `packages/api-handler/src/shell-live.ts` using DO authority.
- Updated `packages/api-handler/src/index.ts` exporting the DO class and routing game-scoped websocket traffic to `/api/shell/games/:id/ws`.
- D1 projection writes for committed state, events, participants, and join requests.
- Replay or `state_sync` reconnect behavior based on `lastEventSeq`.

- Spec references: `docs/RIGHELT_WEB_APP_SPEC.md` Sections 4, 5, 6, 8, 11, 12.1.

  - `packages/api-handler/test/live-transport.test.mjs`

  - `packages/api-handler/test/live-websocket.test.mjs`
- Additions required:
  - concurrent join or move or end-turn serialization tests
  - reconnect replay and `state_sync` fallback tests
  - presence heartbeat and timeout tests
  - route-removal tests proving `/api/shell/ws?scope=...` no longer exists
  - DO restart rehydrate tests from D1 projections and event log

## Gap Tests to Add
- Gap: simultaneous `player2` join and `player1` move or end-turn never fork persisted or pushed state.
- Gap: competing pending player requests resolve deterministically with only one accepted seat outcome.
- Gap: disconnect timeout and reconnect produce the same participant state for all connected clients.

## Regression Focus
- Ensure there is exactly one authoritative write path for game state.
- Prevent future reintroduction of blob-level multi-writer D1 races.
- Protect replay semantics and fallback sync behavior from regressions.
