# Computer-model upgrade retention gate

A model promotion must prove that an existing computer game keeps its original model while new games, branches and rematches use the promoted model. Run this dedicated real cross-version journey separately from ordinary CI. Passing the pure contract tests does not satisfy that release gate.

The root-provided immutable manifest must bind the exact clean old and prospective application checkouts, original and promoted published models, completed numeric proof against the prospective checkout/revision/tree, actual training closure, current authorization, dependency inventory and browser executable. No fallback manifest, fresh-login replacement or fabricated game/receipt is accepted. Candidate selection and exclusive model admission remain prerequisites of the upstream numeric/root protocol.

From the prospective checkout, under one finite grant using the installed released resource supervisor:

```text
NODE RELEASED_TOOLS/scripts/resources/cli.mjs run --kind heavy --timeout-ms GRANTED_BOUND -- NODE scripts/testing/computer-model-retention/driver.mjs MANIFEST_PATH MANIFEST_SHA
```

The uppercase entries describe actual root-supplied paths and values; they are not proof records. The driver takes two positional arguments, not a `--manifest` option. Execution requires the released supervisor's real ownership ancestry, a valid root deadline and an empty private output outside both checkouts. It starts only local account stacks at the same origin.

The journey creates a real old-model account/game and accepted decision, saves original session/storage/history/proof, fully stops the browser and stack, and copies the complete private DB/HMAC state. The prospective stack reopens the same game and owner session, produces another original-model decision, and persists the actual Keep current control. New-game, branch and rematch decisions must bind the promoted model. Reloads must preserve all respective model/history bindings. Raw private evidence and verified owned cleanup are required; incomplete cleanup is not a pass. Preserve both model assets and every game, history, receipt and provenance record. No production activation or deletion is part of this command.

The three `test-*.mjs` modules contain 45 pure synthetic metadata/closure cases. The thin `../test/computer-retention-contracts.test.mjs` wrapper places them in the canonical tooling test inventory and adds one static dependency-boundary case (46 total). They never launch the driver, account stacks, browser or model. The driver is intentionally excluded from automatic test discovery, so a promotion's release checklist must explicitly require successful real retention evidence in addition to normal released integrated validation.
